Court calibration & bounce timing

A new draft, not an overwrite of your original calibration or detections.

Open calibrated 3D replay

The prefilled points and timing changes are proposals. Check line alignment and bounce frames before confirming. At 30 fps, frames are about 33 ms apart; this tool cannot recover an exact sub-frame contact instant.

1. Align actual court lines

Select a named intersection, then click its centre in the image if it needs adjustment. Use painted ground lines—not the net tape. No ball positions are used to fit the court.

Green = lens-aware fit · orange = original projection · numbered points = editable landmarks. Editing a point hides the stale fitted overlay until you export and rebuild.

2. Inspect the bounce one decoded frame at a time

Enlarged raw evidence (no AI enhancement)

A range records uncertainty; it is not a statistical confidence interval. Changing the frame clears a clicked pixel, so it cannot silently carry over to the wrong image.

3. Apply the exported review

Export tennis-calibration-review.json, then run the command below in the project folder. It creates a new replay and calibration desk, with the camera refitted and all landing geometry recomputed. No neural models are rerun.

.\Apply-Court-Review.ps1 -ReviewFile "$env:USERPROFILE\Downloads\tennis-calibration-review.json"

Use the actual exported filename if your browser adds “(1)”. Existing run folders and original court.yaml remain unchanged. Only explicit Confirm actions create confirmed bounce labels; a reviewed calibration alone does not confirm an event.
